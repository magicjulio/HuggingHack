Julius sometimes orders small gameplay or content changes straight to the engineer (2026-10-12: "list all packages right away … add some more packages (real ones that just dont help) … apply those 2 changes"). Apply them directly, fill the small sub-choices sensibly (e.g. decoys cost the normal 5 tokens), log them in DECISIONS as "Julius: …", and tell the storyteller through build-to-story so the script catches up.

**Why:** he owns direction and doesn't want a round trip through the storyteller for small things; he also expects an engineer to know real-world facts (real npm/PyPI package names) without asking research.
**How to apply:** if the change is explicit, build it in the same turn; only ask when a sub-choice changes the game a lot. Related: [[feedback-workflow]].
